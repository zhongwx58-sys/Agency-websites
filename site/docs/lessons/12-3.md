# 有延迟但打不开网页

依次区分 DNS、代理连接、TLS、网站响应与应用请求。

## 明确延迟测试测了什么

客户端显示一个毫秒数，通常只说明其配置的测试任务得到了响应，不代表任意网站和应用都可用。先查看测试目标与方式，再用实际打不开的网站发起新请求。记录浏览器错误、客户端连接和日志，区分没有进入代理、进入后失败以及目标已经返回拒绝响应等情况。

## 沿请求顺序逐层定位

首先检查域名是否解析，再看代理连接是否建立，然后观察 TLS 握手和网站 HTTP 响应。页面主文档能返回但功能不可用时，还要检查后续接口与资源。证书错误、登录要求和目标限流不能简单归类为线路不通，应保存具体错误并按相应层处理。

1. 确认目标请求确实出现在客户端连接中。
2. 记录失败阶段、域名、错误和时间。
3. 同节点测试另一个目标，同目标测试已知可用路径。

## 不要为了消除提示降低验证

出现 TLS 错误时先查系统时间、目标域名和服务参数，不应默认关闭证书验证作为修复。只有某个目标失败时，优先调查该目标相关请求。改变 DNS 或 TUN 后需要重新验证此前可用的目标，避免一个设置暂时改善某个现象却引入其他问题。

## 常见误区

把所有网页错误归于 DNS，或关闭证书验证后宣称根因已解决。

## 恢复与回退

恢复原 DNS、接管和证书验证设置，使用基准目标检查恢复结果。
