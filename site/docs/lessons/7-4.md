# 机场节点接自建 VPS

衔接已部署节点，核对协议与传输能力。

## 先确认落地服务完整

自建 VPS 必须已经部署可用的代理服务，只有服务器 IP 和 SSH 账号不能当作通用代理节点。回到模块 3 的部署记录，找出服务协议、监听端口、认证信息以及 TLS 或传输参数。服务端正常监听和客户端能够访问它属于两个检查环节，防火墙或线路仍可能影响接入。

## 把已知可用节点接入链路

在支持该协议的客户端中保留落地节点原有参数，再增加前置依赖。Mihomo 路线使用落地节点的 dialer-proxy；其他内核按自己的拨号或出站文档配置。先用单一、明确的前置节点测试，确认路径后再考虑自动选择组，便于排查哪个环节发生了变化。

1. 记录前置独立访问测试结果。
2. 检查 VPS 服务监听和对应时间段日志。
3. 组合链路后发起新请求，观察是否到达 VPS。

## 区分入口协议与出口表现

前置和落地可以采用不同协议，但所用内核必须能够完成相应连接，传输能力也要逐项确认。出口检测可能与 VPS 控制台展示的地址不同，例如服务端经其他网关出站。应根据服务端实际路由解释结果，不能只凭节点名字判断。记录最终地址后继续验证目标应用。

## 常见误区

把 SSH 端口直接填成 SOCKS 端口，或链式成功后忽略服务端的实际出口路由。

## 恢复与回退

恢复原客户端节点与服务端配置；一次只回退一个改动，避免丢失定位线索。
