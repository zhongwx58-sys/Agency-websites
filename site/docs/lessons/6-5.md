# DNS 模式与 IPv6

按客户端支持范围讲解模式、IPv4 和 IPv6 检查。

## DNS 模式先限定在一个内核

以 Mihomo 为例，fake-ip 通过映射帮助后续处理目标域名，redir-host 使用真实解析地址的路线。它们是内核的处理方式，不能把同名或相近词直接推广到所有客户端。看到映射地址并不等于目标网站真正位于该网段。

## IPv6 要从头到尾核对

本机是否有 IPv6、DNS 是否返回 AAAA、代理节点能否处理对应连接、规则与接管是否覆盖它，都是不同条件。关闭某个 DNS 的 IPv6 选项，不代表系统中所有 IPv6 流量已经禁用。先查清问题发生在哪一段。

1. 记录当前 DNS 模式与 IPv6 相关选项。
2. 分别观察 IPv4 与 IPv6 目标的新连接。
3. 核对每条连接的实际策略和出口。
4. 使用同一目标或对应测试比较修改前后，保留未能测试的范围。

## 用结果选择设置

如果某个应用与当前模式不兼容，应针对它的实际请求分析，再决定例外或切换方式。不为追求“更高级”而修改已经满足用途的配置。测试要同时检查局域网和日常目标；只修复一个页面却破坏其他访问，不能算完成验证。

## 常见误区

DNS 查询没有返回 AAAA，不等于应用不可能使用已知或缓存的 IPv6 地址。

## 恢复与回退

恢复旧模式与对应 IPv6 选项，重新建立测试连接后检查原有目标。
