# DNS 查询路径

画出目标域名和代理服务器域名的解析与连接关系。

## 画两条独立的查询线

第一条是代理服务器域名如何变成可连接地址；第二条是目标网站域名如何被处理。若连代理服务器也需要先经由尚未连接的代理解析，就可能形成相互依赖。排错时先检查入口域名的可解析与可达，再检查目标域名。

## 把查询位置与连接位置分开

DNS 查询发往哪里、DNS 请求经过什么路径、网站连接走什么出口，是三个问题。使用加密 DNS 也不能单独证明所有查询经代理。Mihomo 提供节点域名等不同用途的解析配置；其他内核要按自己的 DNS 结构理解。

1. 写下代理服务器使用域名还是 IP。
2. 找到节点域名的解析设置与上游。
3. 找到目标域名的解析策略，记录是否有特殊匹配。
4. 查看连接与日志，核对查询和网站访问的实际结果。

## 用最小改动验证判断

遇到解析错误时，先记录失败的是哪个名字以及报错时间。不要同时替换所有 DNS、开关 TUN、关闭 IPv6。保留原设置，只修改与假设直接相关的一项并重新发起请求。缓存和连接复用会影响观察，应记录是否重新建立了连接。

## 常见误区

某个 DNS 检测页面的结果不能直接覆盖设备上所有应用的解析方式。

## 恢复与回退

撤回最近一次 DNS 改动，恢复可用配置；先验证入口解析，再验证目标。
