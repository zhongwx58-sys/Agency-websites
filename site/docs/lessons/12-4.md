# 链式或出口不符合预期

检查节点选择、实际连接、前置与落地顺序。

## 先确认观察的是哪次请求

检测页出口不同于预期时，先找到该检测请求的规则与策略链。它可能命中了直连规则、使用另一组节点，或者走了不同地址族。节点名称与界面选中状态只是配置线索，不能取代实际连接证据。旧长连接也可能保留原路径，应使用新请求进行比较。

## 逐项检查链式依赖

按设备 → 前置 → 落地 → 目标的顺序画图，确认目标策略选择落地，落地又通过正确前置建立连接。Mihomo 检查 dialer-proxy 指向的对象是否存在、是否因为更新改名、组内是否选错节点。不要用两个节点同时出现在列表里证明它们已经串联。

1. 核对最终运行配置中的引用关系。
2. 确认检测请求的实际链路与地址族。
3. 对照落地服务的固定或轮换出口说明。

## 区分正常差异与配置错误

入口服务器地址不一定等于最终出口，轮换住宅服务也可能返回多个地址。若链路符合预期但地址变化，应按服务条件解释；若链路本身不符，先修复规则或依赖。没有服务端或连接证据时保留待核实结论，不用数据库标签反向证明请求一定经过某个节点。

## 常见误区

把入口 IP 与出口 IP 必须相同作为判定条件，或忘记更新后策略选择发生变化。

## 恢复与回退

恢复原链式配置与固定选择，重新建立连接并完成四层验证。
