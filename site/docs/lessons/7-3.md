# 机场节点接住宅代理

逐图填写出口与认证参数，并选择正确的最终出口。

## 准备两组独立材料

先确认已有订阅节点可以独立访问一个测试目标，再整理住宅服务给出的协议、服务器、端口和认证方式。HTTP、SOCKS5 与账号白名单不能互相替代。订单页面写了住宅出口，不代表它提供的就是 SOCKS5；以下片段仅适用于明确支持 SOCKS5 的服务。真实账号与密码保留在本机。

## 给落地添加前置

将示例中的占位值替换为自己的参数，并把前置节点名称改成当前配置中确实存在的名称。片段需合并到已有 Mihomo 配置的 proxies 列表，不能当作完整订阅导入。是否允许 UDP 要按服务和协议实际能力核对，网页能打开并不能证明 UDP 可用。

```yaml
# Mihomo 节点片段，非完整配置
- name: 住宅落地
  type: socks5
  server: proxy.example.com
  port: 1080
  username: REPLACE_WITH_USERNAME
  password: REPLACE_WITH_PASSWORD
  dialer-proxy: 前置节点
```

## 保存、选择与验收

保存到客户端支持的独立配置或扩展配置中，先让客户端检查格式，再让测试请求选择“住宅落地”。访问检测页时记录规则和链路，随后记录 IPv4/IPv6 出口与实际目标访问结果。首版提供参数填写说明和原理示意，尚无对应设备的逐步实拍截图，不能据此认定服务已在你的网络中验证。

## 常见误区

把白名单认证当作账号密码认证，或更新订阅后新增节点被覆盖。

## 恢复与回退

切回原订阅配置；保留住宅参数的脱敏副本，重新确认扩展配置的保存位置。
