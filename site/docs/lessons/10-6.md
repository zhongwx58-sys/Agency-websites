# 版本 备份与恢复

记录系统与内核版本，必要时回退并再次验证。

## 备份能恢复行为的最小集合

至少保留配置正文、个人扩展、必要外部资源说明、客户端与内核版本，以及关键策略当前选择。只保存一个 YAML 或 JSON 文件可能遗漏客户端界面设置和外部订阅条件。备份放在你能找到的位置，文件名写明日期与用途，含凭据的副本不要进入公开同步目录。

## 变更前写一条恢复路径

例如“重新选择原配置文件，恢复原接管模式，再验证两个目标”。这条路径应具体到文件和设置，而不是笼统地写“有问题就还原”。升级内核前阅读迁移说明；若配置使用了新版本字段，单独降级程序可能无法加载，需要配套恢复旧配置。

1. 确认备份可以读取且关键文件齐全。
2. 记录本次升级或修改的目的与范围。
3. 完成变更后执行同一组基础验证。

## 恢复也需要验收

恢复文件后检查当前启用的配置名称、接管开关和新连接路径，然后复测目标访问。不要仅因为程序重新启动就宣布恢复成功。保留失败版本、错误信息和最后成功版本之间的差异，方便以后继续定位。对于涉及驱动或系统权限的改变，还要单独记录系统层状态。

## 常见误区

只备份导出的节点而漏掉规则，或只回退程序却保留不兼容的新配置。

## 恢复与回退

按记录恢复最后可用的程序、配置与接管设置组合，逐项核对结果。
