# DNS WebRTC 与 IPv6

逐图运行相关检测，结合代理设置解释可观察信息。

## 分别观察三种路径

DNS 测试关注解析请求被哪些解析服务处理；WebRTC 测试观察浏览器相关接口产生的候选信息；IPv6 测试关注该地址族的连通性。它们与普通网页请求有关，但不是同一条检测。先记录浏览器、网络、代理接管方式和 DNS 设置，才能解释结果变化。

## 逐项执行并保留状态

在 BrowserLeaks 的 DNS 页面等待本轮测试完成，记录显示的解析器；再打开 WebRTC 页面，保存接口支持及候选信息；最后运行 Test IPv6，保留每个子项成功、失败或未完成的状态。不要把只显示局域网或匿名主机标识的结果直接认作公网泄漏，需要确认地址性质与预期路径。

1. 每项测试单独保存截图、时间与对应客户端设置。
2. 检查检测过程是否被脚本拦截或网络错误中断。
3. 改变一项设置后复测，并对照变化发生在哪一层。

## 根据偏差调整而非盲目关闭

如果 IPv4 与 IPv6 路径不同，先确认接管范围和规则，不要默认所有 IPv6 都应关闭。DNS 显示某个公共解析器也不能单独说明请求绕过代理。需要结合客户端 DNS 流程、系统设置和连接记录判断。首版只提供检测顺序与解释方法，实际截图需按你自己的设备补充。

看到一个陌生 DNS 地址就判定泄漏，或把检测脚本失败写成不存在风险。

## 恢复与回退

撤销本次实验改动，恢复原 DNS 与接管设置，重新检查基本网络连通。
