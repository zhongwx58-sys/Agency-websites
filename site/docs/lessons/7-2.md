# 前置与落地顺序

统一使用设备 → 前置代理 → 落地出口 → 目标网站。

<ProxyLab />

## 顺着请求方向命名

本教程按设备发起请求的方向描述链路：设备 → 前置代理 → 落地出口 → 目标网站。不要依据节点列表的上下位置推断顺序。为了减少混淆，可以把节点明确命名为“前置-A”和“落地-B”，并在备注中写上用途，节点名称本身不会改变转发行为。

## 理解 Mihomo 的引用方向

在 Mihomo 中，为落地节点设置 dialer-proxy，值指向前置节点或前置策略组。意思是建立落地连接时借助这个前置。用于目标请求的规则最终应选择落地节点或含有落地节点的组。只选中前置组并不能自动让请求再经过落地。

```yaml
# Mihomo 配置片段，两个名称必须存在于完整配置中
# 放在落地节点的其他协议参数旁
dialer-proxy: 前置-A

# 对目标请求选择落地-B
# rules:
#   - DOMAIN,example.com,落地-B
```

## 用观测结果检查方向

先查看客户端连接详情中的实际策略链，再打开一个出口检测页。如果检测页走了其他规则，它的结果无法证明目标网站的路径；需要同时确认该检测请求命中了哪个策略。最终出口符合预期以后，还要另行验证实际目标。发现循环引用时，回到路径图逐项核对节点之间的依赖。

## 常见误区

前置引用落地、落地又引用前置，或只把两个节点放入选择组就当成串联。

## 恢复与回退

移除本次新增的前置引用并切回已知可用节点，保留失败时的配置副本供比较。
