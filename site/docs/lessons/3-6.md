# 更新 备份 迁移与停用

管理版本、配置、费用与资源释放，给出恢复和迁移步骤。

## 备份要能恢复

保存内核版本、配置文件、服务启动说明和必要的证书或密钥，并记录它们对应哪台服务器。敏感文件留在受控位置，公开教程只使用脱敏副本。备份的价值在于能恢复出原来的服务，不是目录里多一个压缩包。

## 一次只改变一个主要变量

更新内核之前先阅读对应版本说明。系统升级、协议迁移和客户端换代尽量分开完成，方便比较。迁移到新主机时先并行验证，再切换客户端。

1. 保存旧二进制版本信息和当前配置副本。
2. 在新版本下执行配置检查，处理已弃用字段。
3. 启动后复核日志、监听、客户端连接、出口和实际目标。
4. 新路径稳定符合本次验证要求后，再安排旧资源退出。

## 停用也要有验收

停止服务不一定停止服务器计费。停用前确认需要保存的数据，再在提供方控制台核对实例、附加地址、快照等资源的计费状态。同步撤销不用的凭据，移除客户端失效节点。旧地址释放后可能被重新分配，因此不能继续把它保留为可信连接目标。

## 常见误区

不要在新方案尚未通过验证时删除旧服务器和唯一备份。

## 恢复与回退

新版本失败时恢复对应旧配置和程序版本，再重复最小连接验证。
