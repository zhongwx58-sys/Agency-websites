# IP 进程与应用规则

讲解 CIDR、进程或应用规则及各平台支持差异。

## 选择能够观察到的匹配条件

当请求没有可用域名，或者要针对明确的网段时，可以考虑 IP 条件；当目标是某个应用时，再检查客户端是否能够识别进程或应用。CIDR 的斜线后是前缀长度，不是端口。同一个 CDN 地址可能服务多个网站，因此按 IP 分流的影响范围可能比预期大。

## 先确认系统与接管能力

进程规则需要内核与系统提供相应信息，手机应用选择也取决于系统和客户端。Windows 上看到的进程名不能直接套用到 iOS。先在连接记录中确认请求是否带有进程信息；如果没有，记录这一限制并选择域名等可验证条件，不要仅靠增加进程规则解决不可见的问题。

1. 找到一条目标请求并记录目标 IP、地址族和进程信息。
2. 选择最窄的规则范围，保存原规则位置。
3. 同时测试目标应用与一个无关应用，检查影响范围。

## 留意解析与共享地址

IP 匹配可能涉及域名解析，是否触发解析要结合规则类型及客户端选项理解。IP 地址更新后静态规则也可能失效。维护记录应包含为什么使用 IP、来源时间和复核方法；仅凭一次解析结果长期固定一个公共网站的 IP，容易在地址变化后出现难以解释的分流。

## 常见误区

把 CIDR 当作单个主机地址，或假设所有客户端都有相同的进程规则能力。

## 恢复与回退

移除新加的 IP 或进程规则，恢复原域名规则和兜底策略后复测。
