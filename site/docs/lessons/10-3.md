# Xray 与 sing-box 分支

按各自内核解释结构与示例，避免直接混用配置。

## 相同文件形式不代表相同字段

Xray 和 sing-box 都采用 JSON 风格配置，但字段、协议实现和路由结构各有定义。Xray 的出站使用自己的 protocol、settings 等结构，sing-box 使用自己的 type、tag 与协议字段。转换时应根据原始节点参数重新映射，而不是只把一个字段名称改成另一个。

## 先按版本建立最小路线

记录实际内核版本，打开对应配置文档与迁移说明，先完成一个入站、一个可用出站及明确的路由行为。旧教程中的字段可能已经变更。尤其 DNS、路由动作和出站引用，应根据正在运行的版本核对；如果客户端捆绑内核较旧，不能直接照抄最新文档示例。

1. 导出当前配置并记录内核版本。
2. 按对应内核检查入站、出站、DNS 与路由区域。
3. 使用客户端或内核提供的检查功能，再发起真实连接。

## 迁移时保留行为对照

写下旧配置中的关键行为，例如某域名直连、某目标走固定出口、落地借助前置连接。在新配置逐项实现并复测这些行为。两份配置都能解析不代表行为相同，默认出站和未命中路径尤其需要验证。原始凭据只在本机转换，避免把完整配置上传到不明转换网站。

## 常见误区

因为都是 JSON 就混用字段，或忽略升级后的弃用项。

## 恢复与回退

恢复旧内核与对应配置的组合，保留新配置供继续比较，避免只回退其中一个。
