# 怎样记录好用与不足

按具体网络、时段、用途记录延迟、速度、稳定性和问题。

## 给评价加上条件

“好用”应当落到一个实际任务，例如下班后在家庭网络打开文档站、下载一个文件，或稳定完成一段视频会议。记录测试日期、时段、网络、设备、客户端和节点；离开这些条件，单个速度数字难以用于比较。

## 分别记录不同指标

延迟、吞吐、连接成功率和长连接持续时间不是同一个指标。测试目标也会影响结果。测试本身可能消耗流量，先使用日常任务观察，不需要为了一个分数重复大量下载。

1. 记下操作和预期，例如某个页面需要完整加载。
2. 记录开始时间、成功或失败、错误信息及等待时间。
3. 将客户端延迟与真实任务耗时分两列。
4. 在不同使用时段重复少量同条件观察，保留失败样本。

## 写成别人能理解的反馈

可以写“在所记录的三个时段中，两次完成访问，一次出现连接超时”，而不是写“永久稳定”。若只是依据服务说明，就标注资料整理；只有自己做过的操作才能写为使用反馈。本课程不会把示例记录包装成真实测评，也不根据商业关系排列资源。

## 常见误区

测速网站的表现不能直接推断所有网站、游戏或应用的体验。

## 恢复与回退

遇到不稳定先保存当前证据，再切回可用节点；在记录中注明发生过切换。
