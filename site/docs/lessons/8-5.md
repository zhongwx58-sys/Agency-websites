# 规则集与自定义修改

核对格式、更新方式和自定义规则放置位置。

## 规则集是外部维护的匹配资料

规则集把多条匹配条件放在独立资源中，主配置引用它并指定策略。引用之前要确认发布来源、文件格式和内容类型。Mihomo 的规则集合行为与格式必须和资源匹配；不能把代理订阅、域名列表与完整规则文件当作同一种数据。下载成功仅证明取得了响应，不代表内容正确或已生效。

## 把个人修改放到可持续的位置

远程订阅更新时可能覆盖你直接编辑的原文。优先使用客户端明确支持的扩展规则或独立配置，并记录它是在订阅规则前面还是后面合并。若只是为了一个域名，先添加一条可解释的小规则，避免引入整套来源不明的规则包。

1. 保存当前配置和规则集更新时间。
2. 添加个人规则，检查最终运行列表中的顺序。
3. 手动更新一次订阅，确认个人规则仍存在并命中。

## 检查失效与更新条件

当规则集下载失败时，记录错误、缓存是否存在以及实际加载状态。不要把缓存仍可用误写成远程更新成功。更新后选择一个确实属于集合的域名和一个不属于集合的域名分别验证。若来源变更了格式或内容范围，先在副本中检查，再决定是否替换日常使用版本。

## 常见误区

只看文件大小或 HTTP 成功码就宣布规则有效，或在会被覆盖的生成文件里长期维护规则。

## 恢复与回退

恢复旧规则集与个人规则副本，确认实际使用缓存或固定文件后再排查更新失败。
