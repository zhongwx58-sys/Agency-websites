# 客户端 内核与配置适配

说明订阅格式、内核语法和界面操作的关系。

## 先分清三个层次

客户端提供导入、选择节点和查看连接的界面；内核执行具体网络行为；配置告诉内核怎么接管、解析和转发。相似界面不保证使用相同内核，同一客户端也可能支持多种内核。判断兼容性时，三者都要记录。

## 按配置格式找路线

Mihomo 通常使用 YAML，Xray 和 sing-box 使用各自结构的 JSON；Surge 和 Shadowrocket 也有自己的配置与导入方式。扩展名相同不表示字段相同，单节点分享格式也不等于完整路由配置。

1. 查看客户端“关于”或版本页面，记录界面与内核版本。
2. 查看来源说明支持的导入格式。
3. 先导入一个最小节点或明确适配的订阅。
4. 再逐项添加 DNS、规则和链式，核对支持范围。

## 迁移语义，而非复制文字

跨内核迁移时，先把要求写成“哪个请求，经哪个节点，用什么 DNS”的语言，再在目标内核中分别实现。尤其不要把 Mihomo 的 dialer-proxy 原样写进 Xray 或 sing-box。启动前先进行配置检查，启动后仍需验证实际请求。

## 常见误区

软件能打开文件，只证明读取动作，不一定说明全部字段被正确执行。

## 恢复与回退

迁移在副本中完成，保留旧客户端配置；失败时恢复原路线。
