# 规则顺序与兜底

说明优先级、冲突和未命中时使用的路径。

<ProxyLab />

## 先找更早的匹配项

以 Mihomo 常规规则列表为例，匹配顺序从上向下，先匹配的规则决定这次选择。添加一条规则后没有效果，首先检查它前面是否已有覆盖范围更大的规则。排错时不要只搜索新增规则，还要查看最终运行列表中的实际位置，因为扩展配置可能调整顺序。

## 用一个域名比较两种顺序

假设希望 api.example.com 走指定出口，而其他 example.com 子域使用日常出口，精确规则应放在覆盖整个后缀的规则之前。反过来时，后缀规则已经接住该请求。这里的名称必须与已有策略对应，示例只用于解释顺序。

```yaml
# Mihomo rules 列表片段
- DOMAIN,api.example.com,指定出口
- DOMAIN-SUFFIX,example.com,日常出口
- MATCH,日常出口
```

## 明确未命中时的行为

兜底规则让没有匹配前面条件的请求仍有明确去向。选择直连或代理应由你的使用需求决定，并写入说明。修改兜底影响范围很大，应先选择几个已知域名作对照，分别验证精确规则、后缀规则与未命中路径。其他内核的默认出站机制须按各自文档理解。

## 常见误区

把新规则放到 MATCH 后面，或修改兜底后只测试一个已被精确规则匹配的网站。

## 恢复与回退

恢复规则原顺序和兜底选择，建立新请求后重新核对命中记录。
