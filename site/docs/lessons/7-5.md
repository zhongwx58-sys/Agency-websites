# 按内核配置并保存

分别维护 Mihomo、Xray、sing-box 和苹果客户端的操作。

## 先认清运行的内核

客户端名称不一定等于内核名称。先在关于页或启动日志记录客户端版本与内核版本，再选择对应文档。保存原配置之后新建测试副本，在副本中完成修改。订阅原文、客户端扩展和最终运行配置可能不同，验收时要检查实际生效的内容，而不是仅确认编辑器中保存成功。

## 按各自结构实现相同路径

Mihomo 用 YAML 的 dialer-proxy 引用前置；sing-box 的拨号字段提供 detour 引用出站标签。Xray 使用自己的出站与传输配置，应依当前版本文档确认连接转交方式，不能把其他内核字段直接粘贴进去。Surge 与 Shadowrocket 也应分别使用相应客户端支持的配置和界面，不能视为完全兼容。

## 给配置留一个可恢复版本

建议按日期、内核和用途命名，例如“2026-10-25-mihomo-chain”。在旁边写清新加了哪个落地、引用哪个前置、测试域名和恢复文件位置。先完成解析检查，再选中配置发起新连接。旧 relay 只用于理解与迁移旧文件，新教程不要继续以它作为 Mihomo 主线。

## 常见误区

同为 JSON 就认为 Xray 与 sing-box 兼容，或把苹果客户端的配置直接当作 Mihomo YAML。

## 恢复与回退

重新选择原配置并核对当前运行名称，确认新连接已回到原来的节点与出口。
