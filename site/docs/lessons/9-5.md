# 不同网站结果不一致

先对照规则、连接、IPv4 与 IPv6，再分析数据库差异。

## 先比较原始地址

两个检测网站结果不同，第一步是看 IP 是否相同。如果 IP 不同，优先检查路由、地址族、轮换与测试时刻；如果 IP 相同但城市、运营商或类型不同，再考虑资料库差异。把这两种情况分开，可以避免在配置没有问题时反复修改节点。

## 建立同条件对照

使用同一浏览器、相同客户端模式和固定组内选择，尽量在短时间内打开两站。分别在连接记录中找到它们的域名，记录规则和路径。一个站点使用 IPv6、另一个使用 IPv4 时，展示不同地址并不意外，但两条路径是否符合你的要求仍需要明确检查。

1. 记录站点 A 的时间、IP、地址族和策略链。
2. 记录站点 B 的相同字段。
3. 先解释路径差异，再比较同一 IP 的归属标签。

## 保留无法立即解释的部分

轮换会话、浏览器连接复用或服务端多出口可能让重复测试也出现变化。此时记录变化规律和服务声明，避免挑一个结果作为唯一结论。检测站本身打不开时，注明站点不可达，不把它当作代理必然失效。真正关心的业务目标仍要单独验证，不能由检测站结果代替。

## 常见误区

把所有不同结果都归因于数据库，忽略检测域名使用了不同规则。

## 恢复与回退

固定到一个已知配置重新建立基线，再逐项恢复原先的自动选择或轮换设置。
