# 出口与能力验证

核对出口、IPv4 或 IPv6、TCP 或 UDP 和目标网站访问。

## 先列要验证的能力

网页访问、语音通话和其他应用可能使用不同传输。一个 HTTPS 页面能打开，只说明这次网页请求的相关路径成立。要使用 UDP 或 IPv6，就必须对这项能力另做验证；配置里写了开启选项，不等于服务端与整条链路支持。

## 为每项能力配一项观察

先固定节点和规则，避免自动切换干扰结果。浏览器检测和客户端日志结合查看，才有机会分清哪个请求走了哪条路径。

1. 核对检测站连接记录，再保存本次 IPv4 或 IPv6 出口。
2. 访问实际需要的网站，检查主要功能和相关资源。
3. 如确需 UDP，使用该应用的真实操作并核对连接类型与节点。
4. 分别记录直连、单节点或组合链路的结果，未测项目写未测。

## 写一个有限的结论

例如“本次在此网络上，浏览器请求经选定落地完成，观察到 IPv4 出口；未验证 UDP”。这比写“全部无泄漏”更有用。DNS、WebRTC 和双栈检查放在第 9 模块继续完成；同一设备上，不同应用仍可能遵循不同代理设置。

## 常见误区

SOCKS5 的 udp 开关只表示配置意图，不能代替端到端能力验证。

## 恢复与回退

某项能力失败时回到满足当前任务的可用路径，不同时改动认证与接管方式。
