# 从 VPS 自建到客户端

将开通、部署、连接、维护整理成连续案例。

## 先固定一条完整技术路线

选择已经明确的服务器系统、内核和协议，不要把多个教程的安装脚本与配置片段拼在一起。案例首页写明软件来源、版本、部署日期和适用范围，服务器费用按实际账单记录。此处是记录方法，尚未代替你完成服务器采购或远程部署，也不提供虚构的实测截图。

## 按服务端与客户端两侧取证

服务端记录安装、配置检查、监听端口和服务日志；客户端记录节点参数的脱敏版本、导入过程与首次连接。把服务端日志时间和客户端测试时间对齐，再分别核对链路、出口和目标页面。服务正在运行并不保证公网可达，公网可达也不保证认证和协议协商成功。

1. 保存系统及内核版本，说明安装来源。
2. 保留服务监听与关键日志，遮挡认证材料。
3. 完成客户端接入与目标测试，并记录恢复文件。

## 补齐后续维护与退出

案例必须说明更新、备份、迁移和停用的具体入口，包括配置放在哪里、如何查看服务状态和如何确认资源已释放。对于收费资源，停服务与停止计费不是同一件事，应以服务控制台状态为准。完成后标记哪些步骤实际执行过，哪些仍只是计划，便于读者准确判断可复现范围。

## 常见误区

把服务启动成功直接写成部署全流程可用，或漏掉停用后的资源状态。

## 恢复与回退

恢复服务端和客户端的对应旧配置，先确认已有连接，再继续分析新方案。
