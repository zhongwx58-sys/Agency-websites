# 看懂设备到网站的路径

认识客户端、内核、节点、入口、出口、域名、端口与 DNS。

<ProxyLab />

## 把一次请求画出来

先画“设备 → 代理节点 → 目标网站”。设备上的客户端提供操作界面，内核按照配置建立连接。节点的地址和端口是连接入口；目标网站看到的来源地址是这次请求的出口。入口和出口可能不同，不能根据节点名称推断最终地址。

## 域名先解决找地址的问题

域名方便人记忆，DNS 用来查询地址等记录。代理服务器本身若使用域名，也要先解决它的解析；目标网站的域名则可能由本机或代理路径中的其他位置处理，具体取决于客户端和配置。把这两种查询分开画，排错时会清楚很多。

## 用三种路径做练习

直连由设备当前网络访问目标；单节点让一个代理转发；链式路径可以是“设备 → 前置代理 → 落地出口 → 目标网站”。前置负责帮助连接落地，落地负责向网站发起最后一段连接。图中的箭头表达逻辑顺序，不代表流量已经真实经过。

1. 为每个节点标注角色，不填真实密码。
2. 在最后一个节点旁写“预期出口”。
3. 给设备到入口、节点到目标分别写出可能的失败位置。

## 常见误区

节点列表中的地区名称不等于目标网站实际看到的 IP 归属。

## 恢复与回退

这是一项纸面练习；更改实际链路之前先保留原来的路径记录。
