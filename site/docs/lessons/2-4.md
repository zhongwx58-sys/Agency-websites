# 日常使用与订阅更新

说明节点选择、更新、流量查看与自定义配置保留。

## 更新之前先保存状态

记下当前节点、策略组选择、最近一次通过验证的时间和自定义规则位置。订阅可能改变节点名称，原先引用的名字会因此失效。把自己的修改放在客户端支持的覆写或扩展层，具体用法依据所用客户端，不要把别人的扩展语法直接复制过来。

## 更新后做最小回归

在不影响当前重要任务的时段触发一次更新，查看下载时间与结果。自动更新解决的是内容刷新，不能替代更新后的使用检查。

1. 确认节点数量和分组没有异常变空。
2. 核对手动选择的节点是否仍存在，链式引用是否仍有效。
3. 检查自定义规则的顺序和 DNS 设置。
4. 用同一测试目标重新核对命中规则、出口和网站访问。

## 区分用量和可用性

客户端统计的是它观察到的流量，服务控制台的账单统计可能使用其他口径或存在延迟。先看官方账户中的额度、到期与重置说明，再解释差异。不要为更新失败不断高频重试；保留错误时间与响应信息，确认下载条件后再处理。

## 常见误区

节点名称保持不变也不保证背后的连接参数和出口保持不变。

## 恢复与回退

切回保存的可用配置，保留失败的新版本供比较，再逐项恢复自定义内容。
