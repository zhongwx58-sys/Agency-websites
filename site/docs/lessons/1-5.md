# 核对首次连接结果

看连接记录、实际链路和出口，再检查目标网站访问。

## 先写预期，再看结果

测试前记录时间、网络、配置、模式和节点。写下目标域名以及预期路径。如果预期是代理出口，就不能只凭浏览器打开了页面判定成功，因为页面也可能经直连访问。让每个结论都能对应一条请求和一项观察。

## 按四层检查

从配置到网站逐层核对，能把“配置能用”拆成清楚的结果。出口检测页面只代表它自己的访问路径，目标网站还需要独立检查。

1. 配置层：没有解析错误，当前配置确实已加载。
2. 连接层：新请求命中了预期规则，连接记录显示预期节点或链路。
3. 出口层：打开 IP 检测页面，记录地址、IPv4 或 IPv6 和时间。
4. 应用层：打开实际目标，检查页面资源和所需功能，而非仅看标题。

## 保存足够的证据

把脱敏后的连接记录和检测结果放在同一份笔记中。若检测站与目标网站命中不同规则，注明它们不能互相代替。出现不一致时，重新发起请求并核对缓存、连接复用和双栈路径。结论可以是“本次浏览器请求通过”，无需扩大成所有应用都通过。

## 常见误区

IP 数据库的地区或类型标签不能保证目标平台接受该地址。

## 恢复与回退

验证失败时先回到已知可用的单节点或原网络，再一次检查一个环节。
