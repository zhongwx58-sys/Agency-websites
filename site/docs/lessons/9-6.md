# 形成可复查的检测记录

同时保存检测条件、截图、连接日志、时间和实际访问结果。

## 让别人能够理解测试条件

一张只显示 IP 的截图不足以说明完整路径。记录设备系统、客户端与内核版本、网络类型、接管模式、策略选择、检测时间和时区。公网地址如需对外展示可按用途脱敏，账号、订阅令牌和密码应始终遮挡；保留本机原始记录用于自己核对。

## 把证据放进同一条记录

为每次测试分配一个简单编号，让截图、连接日志和结论使用相同编号。写清预期与实际，不要只填“正常”。下面是可复制的记录骨架，空白字段待你完成实际测试后填写，示例本身没有测试结果。

```text
测试编号：
时间与时区：
系统 / 客户端 / 内核：
网络与接管模式：
测试目标与预期路径：
实际命中规则与链路：
检测 IP / 地址族 / 来源：
目标功能结果：
截图与日志位置：
未测项目与恢复结果：
```

## 写出有限且可复现的结论

例如“本次浏览器访问该检测域名时，命中指定规则并返回记录中的出口；实际目标登录页可加载”比“全局完全正常”更可复查。后续网络或配置变化时保留旧记录，新增一次测试，不覆盖历史。失败记录同样有价值，它能帮助判断问题出现在哪次变更之后。

## 常见误区

截图没有时间或配置条件，或分享日志时暴露订阅链接和认证信息。

## 恢复与回退

保留原始记录，在发布副本中补齐条件并遮挡敏感字段；误公开的令牌需要在服务端更换。
