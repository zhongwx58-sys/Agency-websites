# 域名规则

学习精确、后缀等匹配，辨别同一网站相关域名。

## 从最小匹配范围开始

Mihomo 的 DOMAIN 用于精确域名，DOMAIN-SUFFIX 用于一个域名及它的子域名。先选最小范围完成测试，再根据实际连接补充必要范围。例如主页、登录接口和图片资源可能使用不同域名，只给地址栏中的域名添加规则不一定覆盖整个网站。不要为了省事把一个宽泛关键词全部指定到同一出口。

## 读懂两条教学规则

以下使用保留示例域名，并且假定名为“指定出口”的策略已存在；这是规则片段，不是完整配置。第一条只针对 api.example.com，第二条涵盖 example.org 及其子域。替换成自己的目标前，先用连接记录确认实际请求域名。

```yaml
# Mihomo rules 列表中的片段
- DOMAIN,api.example.com,指定出口
- DOMAIN-SUFFIX,example.org,指定出口
```

## 检查页面背后的请求

打开连接列表后刷新目标页面，按域名或进程筛选，分别查看主要页面、登录和资源请求。浏览器缓存或已有长连接可能让新规则没有立即体现在界面上，优先创建新请求验证。记录仍然不匹配的域名，再判断它是否确属目标必需功能，不要照抄无法解释的大型域名清单。

## 常见误区

误把 example.com.evil.example 当作 example.com 的子域，或把单个页面成功当作全部功能覆盖。

## 恢复与回退

删除本次新增规则或恢复原位置，重新发起请求确认恢复结果。
