# 直接接入与前置接入

根据可达性选择接入方式；需要前置时转到链式代理模块。

## 先尝试解释最简单的路径

直接接入是“设备 → 住宅代理入口 → 目标网站”；前置接入则在设备与住宅入口之间增加一个代理。是否需要前置取决于真实可达性、认证与协议支持，不是住宅属性本身决定。先确认住宅节点参数正确，再分析链路。

## 用一次对照缩小问题

保持住宅节点的地址、端口与账号不变，先记录直接接入的结果。失败时保存错误和时间，检查入口可达与认证。如果已有可用前置，再进入第 7 模块按对应内核配置链式，不要把不同客户端的写法拼在一起。

1. 验证前置节点自己能够完成测试请求。
2. 确认前置可以到达住宅代理入口。
3. 配置组合路径，并选择住宅落地作为最终策略。
4. 重新检查实际链路、来源白名单、最终出口和目标网站。

## 解释多一跳的代价

增加前置会增加依赖与排错环节，也可能增加延迟。它不能修复错误密码或目标网站拒绝，也不能自动补足不支持的 UDP。只有对照证据表明这条路径满足需求，才保留组合；记录每段角色，避免以后更新节点时找不到依赖关系。

## 常见误区

若仅选择了前置节点，网站看到的可能仍是前置出口。

## 恢复与回退

先切回已知可用的单节点，保留失败链路记录，再分段检查。
