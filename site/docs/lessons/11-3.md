# 机场接住宅出口

完整记录参数、链式、分流与最终出口检查。

## 为入口和出口分别建档

用两个独立条目记录前置订阅与住宅出口，写清协议、认证方式、有效期、是否轮换及测试用途。把连接路径画成设备 → 前置 → 落地 → 目标。案例中的商家与体验必须来自真实资料，本课不预填资源推荐或购买结论，未提供的内容标为待记录。

## 完成一条可追踪的测试

先确认前置独立可用，再按模块 7 建立链式。为一个明确目标选择落地路径，并确保出口检测页也走同一路径。分别保存规则命中、策略链、检测地址和目标功能结果。若检测页与实际目标使用不同路径，应如实记录，不能用前者替后者证明出口。

1. 保存落地参数的脱敏配置与前置引用。
2. 记录检测请求和目标请求的独立连接详情。
3. 切换一次前置或更新订阅，再核对落地是否仍正确。

## 解释变化与能力边界

如果服务提供轮换出口，记录会话条件与测试时刻，不将地址变化自动归类为故障。网页成功也不能推导 UDP、所有应用或所有地址族成功。案例结论只覆盖已验证内容，并明确失败时如何退回原单节点配置。首次资料整理与后续实际复现应分开标记状态。

## 常见误区

只展示住宅标签而不展示请求链路，或忽略订阅更新后的引用变化。

## 恢复与回退

切回已知可用的单节点配置，保留链式副本与失败日志继续分段检查。
